# Tenth-microlitre injection steps, and an ID-only tab title — design

Date: 2026-08-21
Status: approved by user (conversation)

Two small, unrelated changes shipped as one package. They share nothing but
a release number; each is a couple of paragraphs, which is why they are in
one spec rather than two.

## A · Injection volume rounds to 0.1 µL

### Problem

14.9.0 rounds the injection volume to the nearest 0.5 µL. Matus works from
a printed *UPLC-MS Injection Volume Guide* whose cells are given to **one
decimal** — `1 drop / 0.1 M → 0.3`, `20× dilution / 0.1 M → 6.0` — and every
cell of it is this plugin's own formula. The plugin should agree with the
table the bench already uses.

The 0.5 µL step was also coarse enough to matter: at the default 0.2 nmol
target the reference entry computes 0.30 µL, which 0.5 µL steps turned into
0.50 µL — two thirds more compound than asked for.

### Decision

`HPLC_INJECTION_STEP_UL` becomes **0.1**, and stays the floor as well as the
step. 0.1 µL is the low end of the injector, and it is exactly where the
printed guide turns red.

**Floating point matters here.** `Math.round(0.3 / 0.1) * 0.1` is
`0.30000000000000004`, which then prints and compares wrong. The rounded
value is normalised — `Number((steps * STEP).toFixed(4))` — before it leaves
`roundToInjectionStep`.

The big number prints to **one decimal** (`0.3 µL`), matching the guide.
The exact volume keeps its existing formatting.

### The `exact …` line becomes conditional

At a 0.5 µL step, rounding almost always moved the amount, so the
`exact 0.30 µL · 0.333 nmol on column` line was almost always worth
reading. At 0.1 µL it usually changes nothing — the reference entry rounds
0.30 to 0.30 — and a line that says "nothing happened" is noise.

So the line renders **only when rounding actually moved the volume**
(`rounded !== volumeUl`, within a small epsilon). That is the same condition
as "the delivered amount is no longer the target", because the two differ
together or not at all.

### Explicitly not in scope

The guide's other edge — an injection above **10 µL**, which the injector
cannot deliver either — is left alone here. Knowing a volume is out of range
is only half an answer; the other half is what to change about the dilution,
and that is the optimiser (feature B), which is being designed separately.
Adding half of it now would mean writing the warning copy twice.

## C · A fourth ELN tab title mode: ID only

### Problem

`eln-title.js` offers three modes: `id-title` (`PHA-MDX-0095 - Reduction of
nitro to amino`), `title-only`, and `original`. There is no way to get just
the autogenerated identifier — `I34E-KRAP-0123` — which is what identifies
the entry when a dozen tabs are open and the titles are long enough to be
cut off anyway.

### Decision

A fourth mode, `id-only`:

```js
case "id-only":
    newTitle = entryId || elnTitle;
    break;
```

Falling back to the title when there is no entry ID matches what `id-title`
already does — a blank tab title would be worse than a slightly wrong one.

A fourth radio in the options card, between *Entry ID and title* and *Title
only*, labelled **Entry ID only** with the sample `I34E-KRAP-0123`.

Nothing else needs touching: `loadElnTitleMode` stores whatever string the
radio carries, and the `switch` already falls through to `id-title` for
anything it does not recognise, so a downgrade to 14.9.0 degrades safely
rather than blanking the tab.

## Verification

The project has no test runner. `roundToInjectionStep` and
`computeInjectionVolume` are checked against the printed guide with the
existing throwaway `node` script — the guide is a ready-made fixture table,
so the new cases are taken straight from it:

| drops / aliquot | M | guide says |
|---|---|---|
| 1 drop (10 µL) | 0.01 | 3.0 |
| 1 drop (10 µL) | 0.04 | 0.8 |
| 1 drop (10 µL) | 0.09 | 0.3 |
| 1 drop (10 µL) | 0.1 | 0.3 |
| 1 drop (10 µL) | 0.3 | 0.1 |
| 20× dilution (0.5 µL) | 0.06 | 10.0 |
| 20× dilution (0.5 µL) | 0.1 | 6.0 |
| 20× dilution (0.5 µL) | 1 | 0.6 |
| 5× dilution (2 µL) | 0.02 | 7.5 |

(all at the guide's own footer values: 0.2 nmol, 1.5 mL vial, 10 µL drop)

Plus a floating-point guard: `roundToInjectionStep(0.3)` must be exactly
`0.3`, not `0.30000000000000004`.

The rest is the usual loop: `npm run build`, reload the unpacked extension
from `dist/`, check the block on entry 2504170 reads `0.3 µL` with no
`exact …` line, and that the new tab-title radio does what it says.

Release: one version bump covering both, per `CLAUDE.md`; the tag is pushed
only on explicit approval.
